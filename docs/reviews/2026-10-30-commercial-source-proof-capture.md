## Borrowed proof observation

The finite commercial graph observes original Pricing sources only after the
original loan quote and the separately retained fee quote reconcile. Original
Physical and current physical/pricing/down/up observations have distinct scopes
and use indexes. The unit wrapper adds unit identity. Historical entrypoints
share exactly the same financial implementation without an observer; generated
observer requests reject before financial preparation.

`SourceProof` is a private borrowed reference with serialization only. The
higher-ranked callback prevents retaining it beyond its invocation. Compile-fail
controls reject escaping the borrow or constructing a forged proof. Observation
adds no financial calls or complete source clones. Existing stopped original
typed economic owners are not recovered: the full retained projection Value is
observed, and acquisition/exercise proof families remain separate.

## Unpublished selected capture

The explicit Rust component reuses existing counted source admission and raw
prefix checks, retaining both complete preparations during revised preparation.
It rejects generated, optional and original Physical acquisition sources in its
initial subset. It has no JSON/API selector or production publication path.

JSONL records retain full source requests, cash, projection, selected fee proof
and original/current role identity. Cancellation, writer failures, exhausted
work, output bounds and failed flushes return no component receipt. Caller-owned
unpublished bytes may remain. The footer and returned receipt explicitly grant

## Independent validation and retained evidence

The Python reference is explicit independent analysis. It derives exact coverage,
order, roles, raw DTO identity and original quotes from the raw request, then
recomputes all six physical and twenty-one pricing records with the independent
credit, cash, carry/accounting and fee references. Captured financial values do
not become expected inputs. Reported source work and memory remain metadata.

inserted recoveries, raw identity, role/weight/order, missing records, quotes and

realized defaults or recovery receipts, so this is not a positive control for
