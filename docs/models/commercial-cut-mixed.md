# Native cut-started commercial coordinator

`commercial-cut-mixed-journal-1` is an explicit raw-source coordinator for a
native commercial Sim prefix and a distinct resumed Sim. The native cut
primitive is implemented and has positive component controls. **The public raw
coordinator fixture currently refuses joined capacity before either graph is
generated. This stage has no accepted end-to-end cut publication.**

## Raw authority and execution

The request contains only `schema`, `cut_ordinal`, `completed_candidate` and
`revised_candidate`. Both candidates use `commercial-candidate-journal-1` and
retain their complete original loan and separate fee histories. The first tier
requires the same origin and complete resolved ledger horizon. Different tails
require a separately admitted complete union and currently reject.

Surviving units, owners, allocations, original quotes, EIR/OAS anchors, source
identity and ordered observed raw prefixes must remain unchanged. Report grids
may add future dates while retaining the exact observed grid. A new candidate
must be appended with actual acquisition strictly after the cut and with the
existing exclusive AC owner and zero opening money. A placeholder's generic
start day does not replace its genuine native source acquisition date.

The coordinator's internal borrowed callback exposes the genuine normalized
Spec, acquired-unit preparation and Compiled native financial owner. It runs
neither ordinary full daily simulation nor ordinary result serialization.
Nested callbacks retain the original and revised source owners while the
native ledger checks their exact observed atomic groups. Public JSON cannot
create this callback or supply a monetary checkpoint.

The ledger executes the original Sim through the cut once, moves all live Sim
state into a distinct resumed Sim, appends future candidates' zero states, and
continues on the original calendar from cut+1. Its state includes gross loan
and fee stocks, coupon lots, basis, pending claims, event cursors, cash, policy
counters, original transaction sequence and minimum-cash/breach history. It does
not reconstruct these from caller balances, refit original yields/spreads or
post a second acquisition for surviving positions.

Protocol 8 emits a signed `native_verified_cut_opening` at transaction 0 and only
future postings after the cut. Prior P&L remains in its original GL; it is not
rolled into new equity. Original future transaction numbers survive. Cut-day
snapshots describe the moved state. Final trial, gross closing statements and
summary counters retain full-origin history; attribution describes future
window events. This differs from the older complete-origin holding-window
route, which replays full daily histories and rolls prior P&L into window equity.

## Admission and current refusal

The raw envelope remains 2 MiB, the encoded result 32 MiB and the joined coordinator
32 million work units / 128 MiB retained capacity. These are component admission
contracts, not an aggregate process-RSS guarantee. The complete cut component
reserves its unchanged 8 million / 32 MiB before either graph generation. It separately
charges numeric posting work, canonical observed-group comparison byte scans,
both typed specifications and comparison buffers.

The borrowed preparation census retains all existing graph source work and the
graph's full existing byte census, including Q/P receipts, retained raw source
bodies and extra genuine Physical owners. It adds construction scans, borrowed
event/binding indices and coefficient storage. It removes only the ordinary
daily/output phase which the callback does not execute. Compiled's own daily
work/byte semantics and guards remain unchanged for the actual cut primitive.
The historical `audit_admitted_work` wrapper and ordinary candidate route retain
their original behavior and complete serialized output.

Each preparation, stream and decoded-table component is bounded at 4 MiB. The
additional Value phase reserves 64 MiB, checks raw comparison clones, admits
dictionary-to-row expansion before cloning decoded rows, and checks the final
encoded-size-times-20 bound before materializing the final Value. All reserves
coexist with the retained source owners. No caller can enlarge these limits.

`examples/models/commercial-cut-mixed-journal-1.json` is a **refusal specimen**:
one surviving loan, one appended future loan, one path in each of baseline and
stress, one fixed coupon per loan, original purchase allocations 50 and 25, a
positive cut at day 3, and a common complete 30-day ledger calendar. The original
ordinary dual-candidate reservation refused at work 37,694,580 and
bytes 184,384,352. The callback-specific census including the complete graph byte
bound now refuses at work 36,844,632 and bytes 223,261,940. Neither is an accepted
economic run. Reducing a component output limit cannot resolve the source work
or source retention refusal.

A reviewed finite source/canonical-retention census must genuinely make an
example admissible before this route can have positive public acceptance.
Transfer-only counted source authority elsewhere does not authorize an
unselected ordinary source in this route. No work-floor change, budget waiver,
caller numeric allowance or silent source-policy substitution is permitted.

## Independent verification and publication

The independent verifier replays both raw graph/acquired-unit preparations and
derives complete ordered loan/fee journals and gross reports from raw owners.
It compares observed unweighted books even at zero allocation. Its cut opening
is the independently accumulated signed journal through the cut; producer
opening balances are never financial inputs. It then checks every future row,
original transaction numbers, retained summary counters, gross closing and
opening-plus-future-to-trial reconciliation.

The API uses the existing durable `/models/runs` worker path and selected
original-byte duplicate-key/size checks. Native execution retains its original
integer deadline; raw requests, source/executable identity and failed admission
survive as durable job evidence. The existing immutable artifact rereads and
private final SQL guards are registered for the new schema. However, accepted
persisted raw-source/cut-journal parity and final-publication mutation controls
remain unproven for this route because its current fixture is refused before
financial generation. Refusal controls must not be described as successful
publication controls.

Native `prior_publication_verified` and `opening_identity_verified` remain false.
The new route does not accept the older prior-publication adapter by implication.
Verified predecessor binding at the exact published cut needs its own explicit
API adapter and acceptance controls. Supplied provenance is not verified prior
publication, legal/accounting policy approval, observed bank opening evidence,
empirical validation or deployment.
