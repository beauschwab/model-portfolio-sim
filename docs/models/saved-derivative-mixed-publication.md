# Saved derivative mixed-source publication proposal

This additive route transports `saved-derivative-mixed-1` to the Rust
`portfolio-model-ledger` dispatcher. Rust rebuilds the explicit saved derivative
source, owns its dated postings in the daily ledger, and streams the single
journal and reports. Python supplies independent verification and durable
storage, never a financial execution alternative.

## Public boundary

`GET /derivatives/mixed/example` supplies the explicit research example.
`POST /derivatives/mixed/runs` accepts `expected_revision`, `specification` and
`timeout`; the worker operation is `saved_derivative.run`. This is a dedicated
raw-source route. It does not change saved-book pricing, Strategy evaluation,
hedge/netting inference, capital permissions or FTP eligibility.

The selected native branch reparses original bytes with duplicate-preserving
strict JSON and checks documented enum strings before source generation. A
tagged object remains an object where the contract requires one. Unit-object
aliases, booleans, nulls and unknown enum strings are rejected. Historical shared
Serde parsers are unchanged.

The immutable original raw JSON value and independently declared normalized
native DTO identities are checked separately. Financial comparisons retain their
existing tolerances; identifiers, reviews, lineage, flags, integer dates, types
and signed zero use exact identity. Neither native result flags nor a saved
trial balance supplies source authority.

## Source and journal verification

The seven `saved_derivative_*` engine modules divide independent financial
equations, mapping, dated accounting, identity, pooled stream replay, transport
and process execution. The private checked control is rebuilt from raw source
and the retained native preparation. It is sealed against post-return mutation.
`verify_stream` replays bounded partition iterators in original transaction order
and independently checks monetary postings, gross source rights, source phase
lineage and reports. Complete source objects and actual protocol-3 completion are
retained; completion is never synthesized from an empty iterator.

Gross rights verification reconciles every retained right. It does not assert
that arbitrary dated backbook future rights were extinguished or grant a closing
capital bridge permission. The durable receipt keeps empirical validation,
accounting-standard approval, capital/FTP eligibility and saved-pricing-graph
adoption false.

## Durable ownership

The server captures the accepted job's finite original deadline before worker
dispatch. Retry does not reset it. Immediate cancellation/deadline checks surround
numerical callbacks; SQL ownership polling is bounded without weakening forced
checks around reads, replay, hashes, uploads and publication.

Queued identity includes the executed binary, current engine identity, all seven
independent helper modules and applicable API/worker/storage code. Mutable
returned job, queue and result views cannot rebase the private authority. Raw,
source, actual completion and Parquet descriptors are immutable and checksummed.
Persisted output and every retained partition body are reread after replay and
within the final publication fence.

The final SQL transaction checks the same queued request/revision, token,
attempt, workspace lease and status before and after I/O. Pure clock/STOP probes
inside that transaction avoid nested repository connections. The worker supplies
`STOP.is_set` explicitly, so the jobs module has no worker import or new cycle.

## Bounds and validation scope

Native financial work remains limited to 8 million units, source owner capacity
to 128 MiB and complete serialized native stream to 32 MiB. Raw input is bounded
to 32 MiB. Strict parsing/enum traversal is separate from the financial-work
counter. These are component limits, not aggregate process RSS guarantees.
Transport separately limits compressed retained partitions to 128 MiB and 65,536
partitions; partition rows are configurable from 1 to 65,536.

Contained evidence uses an actual isolated full Rust dispatcher, the actual
copied worker, SQLite, Codec objects and Parquet reopen. The current-baseline
package passed 221 source, refusal, journal and publication checks. The selected
raw-domain successor passed 13 native tests and strict all-target Clippy and
retains byte-exact canonical source/Sim output. Generated HTTP contracts come
from the actual composed API; the dependency review adds no cycles.

Official-default engine/API and browser acceptance are authored but pending
application, native composition/rebuild and worker restart. SQLite evidence does
not certify PostgreSQL/S3 operation. This stage does not complete issue 20,
empirical calibration, observed validation, or combined 60,000-position scale.
Combining source2 deposits and derivatives in one ledger is a distinct reviewed
raw contract and independent pooled replay gate; standalone results must never
be concatenated to infer that acceptance.
