# Opt-in per-call native graph execution control

This successor is applied locally as part of 0.29.8; matching official native builds and component checks pass, while complete installed-default acceptance remains pending. It follows the immutable market-indexed book and month-360 proposals. It adds execution control to explicit pricing-only indexed graph owners; it does not change product ABI 8 numerical IDs, layouts, prior `portfolio_term_request` payloads, financial formulas, OAS, CRN, cache keys or tolerances. The standalone analytical adapter keeps its existing caller-Control branch.

Python `runtime={schema:"graph-call-control-1",timeout_ms:integer,cancelled:optional callable}` is execution IO, separate from the graph financial request. Timeouts are 1..3,600,000 milliseconds. A cancellation callback must return bool, must perform bounded IO and must tolerate invocation on a helper thread. The monotonic transport deadline starts before the first lease read; native receives floor remaining milliseconds after initial callback readiness. No graph retains a deadline or callback. Every call needs a fresh token and deadline. An expired creation call cannot make future warm calls expire.

The native-owned execution registry permits 256 one-shot tokens. A token starts Fresh, transitions atomically to Running, and becomes Finished on success, failure or unwind. Signalling Fresh or Running sets its shared atomic flag. Reusing a token, signalling Finished, releasing Running or using unknown tokens refuses. IDs never recycle. Unreleased finished tokens still count toward the cap. This small separate registry has a conservative 128 KiB retained allowance; it does not loosen any graph/cache/work/output budgets. Callers must release tokens after completion.

New capability symbols are `portfolio_graph_runtime_version()->u32` (1), `portfolio_graph_cancel_new()->u64` (0 is refusal), `portfolio_graph_cancel_signal(u64)->i32`, `portfolio_graph_cancel_release(u64)->i32` (1 success, 0 refusal), and `portfolio_term_graph_controlled(const u8*,size_t,u64 token,u64 timeout_ms)->char*`. The input range must remain live for the synchronous call. Result allocations must be freed exactly once by unchanged `portfolio_term_free`. No callbacks or pointers survive the call. All calls use the same captured loaded artifact as the actor. Missing symbols or wrong capability version raise `NATIVE_GRAPH_CONTROL_REQUIRED`, requiring rebuild/restart; no uncontrolled fallback is permitted.

Controlled operations admit only typed indexed creation, matching indexed price, info and clear. Wrong-owner requests, legacy financial requests and controlled drop refuse before acquiring the owner lock. Drop remains an unconditional bounded resource cleanup using the existing entrypoint. Initial generation remains outside the global owner registry lock. Control propagates into the actual Rayon worker scope, existing financial checkpoints, a 1 ms owner try-lock wait loop, bounded output serialization writes and final CString allocation/handoff. JSON parsing, individual allocation and finite mathematical kernels are not interruptible inside a single operation; checks before/after retain bounded cooperative scope. There is no hard interrupt or aggregate RSS guarantee.

A creation result is not handed off until the last check succeeds. Any error or late cancellation/deadline retires its registered unpublished handle; existing actors remain owned on pricing failure. Python polls lease IO every 50 ms during native execution and performs fresh bounded reads after native return and after JSON decoding. Exceptions, non-bool returns and reads exceeding 250 ms fail closed. A stalled daemon IO reader cannot be forcibly stopped; callers must provide bounded IO, and the existing worker/watchdog and final atomic publication checks remain required. Native cancellation tests and process watchdog termination are separate evidence. Python cleanup retires only this invocation's newly created actor through its captured library and frees its response once.

Contained native tests cover token cap/state/reuse, pre-cancel, invalid timeout, actual owner-lock cancellation/deadline, independent concurrent tokens, late handoff rollback, fresh warm deadlines and response compatibility. Installed-default control process tests passed in the first full engine run; that run failed a separate mortgage capital test fixture, so complete default acceptance is being rerun. Durable indexed-book publication remains a separate unapplied proposal. This successor adds no saved-book/library/cohort, Physical, accounting, capital, FTP, empirical, calibration or joint stochastic adoption. Source/reference identities remain exact; runtime fields do not rewrite original supplied OAS or financial parents.

Integration documentation must append these exports to `docs/models/native-contracts.md` and `docs/contracts/native-abi-layouts.md` (additive capability, not new buffer ABI). The schema/architecture checks should inventory the new execution module and Python IO-only helper. Numeric ABI-8 manifest remains unchanged.

A cold public book call may create and then price through two native calls; each receives a fresh per-call runtime. A whole-job deadline/lease must remain enforced by the outer durable worker and final publication guard. This change does not add RunConfig financial fields or automatically transport worker controls where no explicit caller opts in.

Tokens and graph handles are scoped to their originating loaded library. Bare u64 IDs can coincide in two libraries; direct C callers must never pass a foreign token/handle, and native rejection of such collisions is not claimed. Python captures the actor library for token creation, invocation, signal, release, cleanup and response free; path/artifact stamp drift rejects financial actor operations before invocation. Cleanup continues through the captured library even when the environment changes.
