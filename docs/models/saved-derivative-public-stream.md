# Selected saved derivative stream adoption

This is an isolated source-adoption stage for issue #20. It moves the verified
`saved-derivative-mixed-1` coordinator into a proposed reusable Decision module and
adds a selected branch to the actual modeled-ledger dispatcher. Matching public
worker/API/saved-book acceptance remains required. The installed851 FTP bundle is
not changed by this proposal.

## Financial ownership

The existing native Risk saved-derivative source reconstructs raw trade terms,
contractual schedules, reviewed legal mapping, separate Pricing/Physical inputs,
collateral and closeout. The existing Ledger exclusive derivative owner receives
generated typed intents and opening stocks; it runs them through the actual shared
dated daily Sim and GL. The Decision coordinator binds source/run/account identities,
admits work, prepares each native source once and invokes that shared runner.

The public stream wrapper performs original-byte admission, bounded serialization
and checked output. It introduces no second coupon, option, exposure, collateral,
credit-loss or journal calculation. Generic owners cannot post a second copy of
derivative economics. Actual combined cash/equity are posted once; source custody
memo remains separate from financial GL, with gross derivative/collateral/unpaid
stocks retained through complete tails. See `saved-derivative-mixed.md` for the
financial contract and `saved-derivative-integration-plan.md` for full issue scope.

## Explicit public envelope and output

The proposed selected process accepts exactly:

```json
{"request":{"schema":"saved-derivative-mixed-1","dated":{},"owners":[]},"execution_timeout_ms":60000}
```

The empty nested objects above illustrate the envelope only; they are not valid
financial inputs. Complete dated sources, account opening anchors and every saved
owner/scenario source are mandatory. Timeout must be a valid positive native integer;
boolean, fractional, zero and unknown envelope fields reject. The original-byte
shared parser rejects duplicate object keys at every depth and trailing documents.
The selected original request retains JSON number categories and signed zero.

The first NDJSON record is a `workflow` header with
`schema="model-ledger-preparation-1"` and
`model_schema="saved-derivative-mixed-1"`. It retains both the original selected
request and the native source receipt with immutable original request, complete
native sources, joined work, owner capacity and explicit permission flags.
Subsequent records are the actual ordered shared journal/report stream, including
derivative source, opening and custody lineage. Exactly one actual native
`{"complete":true,"protocol":3}` record terminates the stream.

Financial source generation, full shared simulation and complete header/stream
byte admission finish before any header is emitted. Write, chunk and flush failures
propagate. Native control checks cover the scoped financial execution and output;
the transport watchdog and original accepted queue-time deadline must additionally
cover input, persistence and final publication in the remaining durable integration.
A native completion record alone is not a successful publication receipt.

accounting, complete source lineage, every ordered shared posting, once-only combined
opening and daily gross statements. Its seasoned successor also verifies asset and
funding premiums/discounts, gross accrued opening rights, immediate source fees,

floating-point rights residues and existing final-output tolerances. Arbitrary
extra GL owners and altered raw source/posting evidence reject.
