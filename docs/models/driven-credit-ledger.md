# Frozen covariate drivers to realized credit ledger

`driven-credit-ledger-1` is a native preparation contract. It composes the frozen `credit-covariate-1` physical hazard projection with explicit realized path/accounting policies and a raw `credit-path-ledger-1` specification. Rust performs the projection and ledger admission. Preparation emits no financial journal rows; protocol 5 execution evaluates each financial batch once in staged output. Existing supplied-hazard path, protocol 4 credit and legacy daily routes retain their own economics.

The public Rust interface is `driven_credit::prepare(&Request) -> Result<Prepared,String>`, with `prepare_with_limits` for a caller's smaller native position/work tier. `Prepared` contains the raw protocol 5 `ledger` request and a `receipt`. Compilation validates full baseline/scenario/reverse coverage, ownership, opening anchors, account reconciliation and ledger admission before preparation returns. Per-batch accounting domain, conservation and claim checks remain the execution gate. A structurally prepared request is not an independently verified published ledger.

## Inputs and ownership

The strict request contains schema, execution use policy, currency unit, as-of ordinal, raw specification, deadline and explicitly identified runs/batches. Each batch contains exactly one position/path/binding, its account, a frozen projection request and an accounting template. This initial preparation tier does not group heterogeneous hazards into a shared multi-position path contract.

`AccountingTemplate` uses the existing `DayMapping`, `PathBinding`, `DrawStream`, `PathOpening` and `PathBoundary` types. Its `PathTemplate` retains source revision, original opening amounts and live state, boundaries, CRN stream and path key. Its `PolicyInterval` contains an exact end date/time, three signed accrual rates, LGD, CCF, interest-recovery fractions and complete per-origin recovery tails. There is no hazard field. Unknown fields reject, so a caller cannot substitute, multiply or overwrite native projected hazards.

The position, scenario, physical measure, as-of midnight, reporting endpoint, model-policy ID and interval counts must match the projection. Every policy interval must end at precisely the corresponding driver endpoint; missing driver intervals, unavailable covariates and incomplete paths reject in the shared projector. Projection uses supplied frozen feature transforms and parameter identities. The fitted model checksum and the raw driver vintage are retained. No P-to-Q conversion, driver forecast, missing feature substitution or clipping of excessive projected hazard is inferred.

The shared projector produces annual continuous intensities. For driver interval ending at time `b`, the path end is `(b - as_of) / (365 * 86400)` years under ACT/365 elapsed seconds. The existing path engine integrates the competing hazard clock across those boundaries without redrawing at a driver change. A realized account's principal, commitment, accrued rights and basis remain absolute amounts; no second probability factor is applied. Scheduled repayment/draw/maturity and reviewed allowance/chargeoff/recovery policy continue to belong to their explicitly supplied path/accounting contracts.

The complete serialized CRN stream and opening account state must be byte-identical for a position across baseline, scenarios and severity-reverse runs. Both supplied uniforms and the versioned counter stream are preserved, including stream revision, seed and integer path key. Driver paths may change hazard/event timing, while common draws remain common.

## Execution use and evidence

`use_policy.kind = adoption` requires every projector to request adoption output and pass its native model eligibility gate. `research_analytical_only` requires a nonempty reviewed identity and rationale, and every projector must request analytical-only output. Mixing these modes rejects. Research preparation explicitly reports `research_only=true` and `adoption_output=false`; it cannot silently become an adoption result.

Every receipt retains the complete normalized typed raw request, every projected interval and its driver/model revision, plus run/severity/account/batch/position/path identity. It reports preparation bounds, actual shared projection work and admitted ledger work. `empirical_validation` and `regulatory_compliance` remain false in both modes: numerical adoption eligibility does not establish that caller-supplied histories are authentic, representative or independently approved. Production publication must retain raw inputs and receipt, independently recompute driver hazards and realized/accounting outcomes, replay persisted GL, and pass immutable publication/deadline/cancellation gates. Prepared hazards alone are not source truth.

The shared estimation likelihood and feature transform assumptions are documented in [credit covariate calibration](credit-covariate.md), with the [ETH piecewise constant hazard reference](https://www.stat.ethz.ch/CRAN/web/packages/eha/vignettes/tpchreg.html). Exact event-time integration follows the shared [credit path model](credit-path.md) and its [temporal Gillespie reference](https://journals.plos.org/ploscompbiol/article?id=10.1371/journal.pcbi.1004579). These modeling references do not establish regulatory accounting approval.

## Bounds and validation

The initial preparation tier admits at most 4,096 generated batches across all runs, 50,000 aggregate driver intervals, 64 MiB serialized input/prepared request, and a conservative 20 million preparation work bound (`serialized input bytes + 256 * driver interval count`). Actual shared projection work also cannot exceed 20 million. These are component ceilings, not measured 60,000-position portfolio acceptance. The underlying ledger's 60,000-position/90-million-work maximum remains a separate upper bound; caller limits may be smaller. Full recovery tails, source metadata and common-draw payloads count in input admission before projection or receipt cloning.

Local deadline checks cover serialization, per-batch projection and preparation stages. Each projector receives the smaller of its valid supplied timeout and the remaining request budget. Existing native cooperative control checkpoints remain active. The root execution and publication watchdog must include preparation, streamed replay, verification and final publication; this module does not establish a process-wide RSS cap or interrupt arbitrary arithmetic inside every shared primitive.

Independent native fixtures cover the synthetic macro fit with hazards 0.25 and 0.5 per year, a common half-day-baseline default draw, contingent EAD draw and complete recoveries. Baseline/stress final cash and equity are 66.05 and 66.025, with no extra modeled-loss deduction. A separate two-interval hand case crosses a driver boundary using one waiting draw and reconciles exact earned interest. Fixtures reject injected hazard fields, altered coefficient checksums, unavailable drivers, calendar/policy/measure mismatch, scenario CRN changes, missing reverse coverage, opening reconciliation failure and bounded/cancelled requests. The example is explicitly synthetic research input; fixtures are not empirical model validation or full publication acceptance.
