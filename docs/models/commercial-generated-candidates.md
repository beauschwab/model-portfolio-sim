# Generated commercial candidate journals

`commercial-generated-candidate-journal-1` is an explicit generated-source
execution tier. The raw request uses the same commercial unit, actual purchase,
allocation, owner and run mappings as `commercial-candidate-journal-1`. Every
selected position must instead own a genuine `commercial-generated-policy-1`
recipe. Ordinary finite candidate admission is unchanged.

## Financial ownership

The existing native graph trains continuation on Pricing training observations,
retains independent evaluation and Physical laws, and freezes the one original
OAS. Physical acquisition cost and original effective yield continue to bind the
separately verified original stopped Physical cash distribution. The journal
accepts no caller monetary checkpoint, replacement original proof, cash receipt
or stopping decision. Missing or foreign acquisition authority fails inside the
same existing native Physical source owner.

After emitting graph/source metadata, execution consumes the prepared unit
owner. Pricing sources, original public receipts, funding and coefficient buffers
are released before Physical accounting materialization. Each current Physical
recipe then constructs one genuine complete source/accounting owner, copies a
sealed journal-only representation, and drops that expanded owner before the next
recipe is materialized. The original native acquisition proof is shared by an
`Arc`; its public JSON is serialized directly from that authority. It is not
retained again as a second owned JSON tree. Historical finite proof JSON keeps its
original representation. Generated proof JSON retains complete canonical content;
typed map emission can differ in key order from older Value-based emission.

The compact representation interns posting/policy/coupon identities and retains
the original atomic postings, native event clocks, complete absolute snapshots,
separate gross coupon origins and reviewed recovery claims. Monetary endpoints
are never reconstructed by accumulating compact endpoint differences. The
existing daily Sim remains the only journal coordinator. Per-run ordering is
day, global native year, binding index, native group index. Actual purchase
offsets are retained. The explicitly supplied generated journal calendar may run
longer than the graph reporting grid, up to 1,080 days. It retains the exact last
native endpoints after the complete source tail; it invents no coupon, default,
recovery, maturity or cash beyond that complete source. An event just after a day boundary cannot be rounded into
the preceding day.

An allocated face `A`, unit face `F`, and Physical path probability `w` apply the
single factor `(A / F) * w` to native journal money. Original cost/EIR and native
cash, legal and recognized rights remain unweighted source evidence. Zero face
allocation still retains and verifies the complete unweighted path. Principal
settlement does not remove later coupon or recovery rights. Signed recognized
coupon lots retain their independent asset/liability classification.

## Bounds and output protocol

The selected graph/journal workflow retains the generated four-billion work and
128 MiB conservative capacity tier. It separately enforces the native ledger
eight-million work and 32 MiB retained accounting limits. Graph metadata and
accounting phases can use the maximum of their reservations only because native
ownership consumes and drops the first phase before the second starts. Raw input,
retained Physical recipes/shared proof, one expanded owner and compact accounting
are charged for their actual coexisting phase. These capacities are not a total
process RSS guarantee.

For compact numeric work, let `L` be the largest retained gross lot count for a
path, `R` the sum of posting, two gross-lot and group rows, `D` the number of daily
calendar points, and `A` the account count. Event staging/reconciliation reserves
`4 R (2 L + 32)` units: stock-key searches remain linear, so this includes their
quadratic worst case in `L`. Daily expected/gross scans reserve
`8 D (A + 1) (3 L + 12)` units and snapshot selection reserves `4 D (L + 1)`.
Every account's gross scan is charged because it traverses all owned paths before
account filtering. The borrowed historical work formula is unchanged. Native
controls require monotone lot/account/calendar charges and refuse arithmetic
overflow and a large-lot/late-calendar workload before Sim execution.

The process entrypoint accepts an envelope with
`op="analyze_commercial_generated_candidate_journal"`, the explicit schema,
`execution_timeout_ms`, and `request`. The standalone
`portfolio-model-ledger` dispatcher retains the original process-entry deadline.
Output is NDJSON rather than an enlarged complete JSON result:

1. A workflow header carries the immutable raw request, resolved specification,
   allocation replay, reporting/full-tail dates and admission/source counts.
2. Separate metadata tables carry coefficients, graph metadata, individual
   current/original sources and acquisition proofs. Every metadata row has
   `unit_index`, `source_index`, and a lossless `native_json` object; persistence
   encodes that object as lossless JSON text.
3. The same existing Sim emits protocol 6 journal and report records followed by
   its genuine producer completion.
4. A separate `commercial_generated_complete` trailer binds source count,
   maximum one expanded Physical owner, full-tail date and explicit adoption
   flags. Neither a missing Sim completion nor a missing trailer is success.

Each record including its newline is bounded to 32 MiB. JSON is encoded directly
to a checked writer; a complete proof/output buffer is not allocated. Persistence
uses bounded immutable Parquet partitions. The selected transport tier admits
one MiB raw input, 32 MiB records/partitions, a 16 MiB manifest, at most 65,536
objects, 512 MiB aggregate serialized content and two GiB cumulative decoded and
logical content. These are explicit phase limits; ordinary historical importer
and buffered candidate limits are unchanged.

## Independent verification and publication

`commercial_generated_candidate_reference` independently regenerates seeded
laws, fits continuation, verifies original acquisition cash and recomputes
coefficients from raw sources. Temporary bounded SQLite sequences retain
independent accounting groups, sorted expected events, transaction comparisons
and gross snapshot histories. The report verifier compares rows against persisted
partitions as they are generated. It does not concatenate complete journal or
daily tables into one result. Temporary storage is removed on success, refusal,
deadline or cancellation.

Verification checks exact metadata order/coverage, current/original raw ownership,
original quote/OAS/EIR/cost, actual purchase offsets, once-only face/probability
weighting, complete ordered journal lines, gross daily/closing books, trial
balance and all Sim reports. Missing, duplicated, reordered or tampered source
records and a validly rehashed but changed journal still fail independent replay.
Persisted verification, source/artifact rereads and original deadline,
cancellation, executable, request/revision/attempt/token/lease and final SQL
publication fences remain required. Partial streams confer no publication
authority.

## Scope and acceptance

The synthetic example is
`examples/models/commercial-generated-candidate-journal-1.json`. The native
minimum-sample control requires genuine generated Physical paths for baseline
and a separately supplied nonbaseline scenario. Larger output controls must prove
partitioned output beyond the historical 32 MiB buffered envelope without raising
that old limit. Compact and borrowed financial controls retain unchanged output
tolerances. The native/schema and persisted tests are local implementation
evidence; they are not observed-model or accounting-policy approval.

The one-day synthetic source with an explicitly selected 100-day outer journal
emits **33,825,744 bytes**, through a counting sink that retains no complete
output. Its financial source clocks, original quote and full cash tail are
unchanged. Compact/borrowed comparison decodes each stream's own dictionary:
interning zero-valued endpoint names can assign different integer dictionary
indices while the complete ordered monetary rows/transactions remain equal.
Every compact native atomic group is additionally compared byte for byte with
its borrowed original. Separate controls exercise signed coupon rights,
controlled defaults/recovery, actual native stopping and zero participation.

The same100-day case also passes actual bounded Parquet persistence and complete
independent raw-source, ordered journal and report replay, including25,856 gross
daily source rows. Eleven actual native/persisted engine controls pass, including
missing, duplicate, reordered and corrupted metadata, source groups, postings,
gross snapshots, producer authority and cancellation. Public durable API source,
artifact and final-publication fences were validated separately. These local
controls retain unchanged final numerical tolerances and ordinary admission.

The generated route does not implicitly adopt nonintegral fee Pricing exercise,
arbitrary mixed owners, AFS/HTM marks, institution funding liabilities, saved-book
or cohort sources, regulatory policy, observed calibration, general convergence
or the complete 60,000-position joint graph/credit/solver/journal gate. Those
remain explicit requirements of issues 15 and 25. Interactive evaluation remains
coefficient-only. Matching artifacts and explicit selected library/session
rebuilds are required before additive execution; local implementation does not
restart deployed workers.
