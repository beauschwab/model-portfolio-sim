# Generated commercial candidate publication

The explicit `commercial-generated-candidate-journal-1` contract prepares actual
purchase coefficients and replays generated Physical sources in the existing
native daily Sim. It is a separate capacity tier from the finite, materialized
`commercial-candidate-journal-1` result. Neither route silently upgrades a saved
book or provides observed model validation.

Submit the raw example in
`examples/models/commercial-generated-candidate-journal-1.json` as `specification`
to `POST /balance-stress/modeled`, with the current `expected_revision`. The API
queues the existing durable modeled-ledger operation. The original accepted
1,800-second budget covers queueing, native preparation, streaming, uploads,
independent persisted replay and final SQL publication. A retry retains that
original deadline. `large_book` does not enlarge the generated tier.

## Native ownership and stream

`portfolio-model-ledger` dispatches the explicit generated operation to the native
commercial candidate coordinator. Supplied Pricing training and independent
evaluation, paired Pricing bumps, original OAS and the original Physical
acquisition proof remain owned by the graph. Participation and allocation scale
each native source exactly once. A zero allocation retains the complete source
policy and tail rather than erasing its provenance.

Generated accounting preparation expands at most one full Physical owner at a
time. Sealed compact sources retain atomic postings, absolute monetary endpoints
and gross coupon lots. The daily Sim consumes those sources in native scenario,
calendar-day, credit-clock, binding and atomic-group order. Source cash and
recovery tails determine the complete replay horizon independently of the
requested report date. No synthetic terminal payoff is introduced.

The generated route may explicitly select an outer journal calendar extending
beyond those complete source tails, within the existing 1,080-day journal bound.
Its report grid must still lie within the genuine source tail. The later journal
days retain exact closing source endpoints and create no loan interest, defaults,
recoveries or settlement cash. Historical finite candidates retain their exact
source/journal horizon rule. Extending the reporting grid requires a genuinely
longer source and fresh graph admission; a longer outer calendar cannot supply it.

The native output is newline-delimited JSON:

1. One workflow header binds raw input, resolved specification, allocation replay,
   source admission, full/reporting dates and generated-path coverage.
2. Bounded per-unit coefficient/graph records and per-source original/current
   records retain exact native objects. Their storage tables use integer
   `unit_index`/`source_index` and lossless canonical `native_json` cells.
3. The existing protocol-six journal and report records stream directly from Sim.
4. The protocol-six completion is followed by exactly one generated coordinator
   trailer. The trailer binds path counts and full dates; its verification,
   opening-evidence, mixed-adoption and empirical flags remain false.

The selected transport refuses duplicate JSON keys, nonfinite values, oversized
or truncated records, missing or repeated completions, and any subsequent data.
Historical routes keep their existing completion protocol and reject trailers.

## Explicit phase bounds

Native financial admission remains the generated four-billion-work/128-MiB
retained-component tier, with the ordinary finite source limits unchanged.
These limits are distinct from storage admission:

| Component | Selected generated bound |
|---|---:|
| Raw native envelope | 1 MiB |
| Native record or persisted Parquet object | 32 MiB |
| Sim completion / coordinator trailer | 128 bytes / 8 KiB |
| Local partition manifest | 16 MiB |
| Simultaneously buffered transport tables | 8 MiB flush threshold |
| Aggregate serialized storage phase | 512 MiB |
| Aggregate decoded-column and logical-row phases | 2 GiB each |
| Immutable objects | 65,536 |
| Rows per Parquet partition | 1–65,536 |

One metadata source is flushed before the next is accepted. A single bounded
incoming record and decoder allocations are additional to the buffer threshold.
Parquet metadata is checked before table decoding, including logical repeated
string expansion. Component and phase limits are not a combined RSS guarantee.
The independent verifier uses a bounded temporary disk spool rather than retaining
all expanded path accounting owners. These are transport/work bounds, not new
economic approximations or relaxed financial tolerances.

## Verification and final authority

The engine retains raw input, preparation, Sim completion and generated trailer
as separate immutable files. Independent references reconstruct graph laws,
training/evaluation separation, stopped cash, original acquisition anchors,
coefficients, allocation, exact source order, journal transactions, gross rights,
daily reports and complete closing claims. The verification reads persisted
partitions one at a time.

The API imports those partitions through the existing local/S3 object store and
retains source files as managed object references. Uploaded raw sources and
partitions are independently replayed again before the final SQL guard. That
guard checks every immutable descriptor and raw queued authority, the original
deadline, source and executable identities, current workspace revision, attempt,
lease, owner token and cancellation. Source/trailer objects remain reachable for
reopening and garbage collection. Table pages and downloads consume partitions.

Failed verification, expired ownership or cancellation must publish no accepted
result. Engine publication removes only its fresh, owned unpublished directory
if a final post-rename fence fails. No existing artifact or historical result is
rewritten.

## Remaining acceptance

This route does not itself complete path-specific generated draws/reviewed credit
actions, fee ownership, seasoned or mixed backbooks, observed predictive holdouts,
reviewed accounting/regulatory policies or the combined 60,000-position
graph/credit/solver/journal gate. Those original requirements remain in
`commercial-completion-plan.md`, `implementation-plan.md` and issues 15/25.
Matching native artifacts and explicit saved-library/session rebuilds are required
for additive execution. Local implementation and tests do not deploy services or
restart production workers.
